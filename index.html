Hive warehouse, step by step
Explained simply Simulator What the lab teaches

Turn a pile of JSON into a warehouse you can ask questions of.

In this lab you put Apache Hive on top of the two million events from lab 3.1. You will give the data table names, split it into one folder per day so questions about one day read one folder, store it in a smaller, faster format, and finally ask a real security question. First the ideas in plain words, then every command in a simulator.

Each drawer is one day of events (one partition). A question about 5 August opens one drawer instead of all twenty. That one trick is the biggest speed-up in a warehouse.

Explained simply

Read these nine ideas before the simulator. Each one is used in a step of the lab.

1What is a data warehouse?

A place where data is kept and organised for asking questions about the past: "which host moved the most data last week?" It is different from the database behind an app, which is organised for quickly saving and reading one record at a time.

Think of it as a well-organised archive room, not the cash register.

2What is Hive?

Hive lets you write SQL against files that sit in HDFS. It translates each query into a MapReduce job, which YARN runs on the cluster, and the job reads the files.

your SQL›Hive›MapReduce job on YARN›files in HDFS

That is why even a small query takes 15 to 20 seconds in the lab: starting a job has a fixed cost.

3The metastore: Hive's catalogue

Hive keeps a list of every table: its name, columns, file format and where its files are. That list is the metastore. In the lab it is a small Derby database in a folder called metastore_db.

Derby allows one user at a time, and it lives in the folder where you started Hive. Start Hive from a different folder and you get a new, empty catalogue. Always start from /opt/hive.

4Schema on read

A normal database checks your data when you load it (schema on write). Hive does not check anything at load time. It applies the column names and types when you read. If a field is missing or the wrong type, you simply get NULL in the result.

Loading is instant and free, but nobody stops bad data getting in. Data quality becomes your job.

5Managed and external tables

Managed
Hive owns the files, in its warehouse folder. DROP deletes the data.
External
Hive only points at files that live elsewhere. DROP deletes only the definition.

Rule: if you did not create the files with Hive, the table must be EXTERNAL.

6Partitions are folders

A partitioned table stores each value of a column in its own folder, for example event_date=2026-08-05/. The date is not even stored inside the files; it is the folder name. A query that filters on the date reads only the matching folder: partition pruning.

Partition by what you filter on (almost always a date) and never by something with thousands of values, like an IP address.

7Buckets are boxes inside a folder

Bucketing splits each partition into a fixed number of files by a hash of a column. Here, 16 files by host: every host always lands in the same file.

12345678910111213141516

Useful for two things only: sampling ("give me 1 of 16 boxes") and joining two tables bucketed the same way.

8Row files and column files

JSON (by row)
To add up one column, read every whole row.
Parquet (by column)
Read only the column you need.

Parquet also compresses well, because similar values sit next to each other.

9Window functions

A window function compares each row with a group of related rows, without collapsing them the way GROUP BY does. In step 10 each host's day is compared with that same host's average day.

hostdaybyteshost's avg
host04208-11128 M143 M
host04208-12389 M143 M
host04208-13131 M143 M

"Unusual for this host" catches more than "biggest host overall".

Words you will meet

HDFS
Hadoop's distributed file system, where events.json and all table files live.
YARN
Hadoop's job manager. It runs the MapReduce jobs Hive creates. Its web page is on port 8088.
MapReduce
The engine Hive uses here: mappers read and filter file pieces in parallel, reducers combine their results.
SerDe
Serializer/Deserializer: the plug-in that turns a file's bytes into columns, here JSON into columns.
CTAS
CREATE TABLE … AS SELECT: make a new table and fill it from a query in one statement.
EXPLAIN
Shows Hive's plan for a query without running it: which folders it will read, and how.
Parquet
A column-oriented file format: smaller files, and fast when a query needs few columns.
Derby
A tiny database embedded in Hive for the lab's metastore. One connection at a time.

What this lab teaches

    

      

        
    
          
  1. A Hive table is a description of files. The metastore holds the description; HDFS holds the files. Creating a table checks nothing, so wrong data shows up later as NULLs (schema on read).
    2. 
          
  2. EXTERNAL for data you did not create. Dropping the managed table deleted its folder. Dropping the external table left events.json untouched. Getting this wrong on shared data deletes it for everyone.
    3. 
          
  3. Partitions are folders, and pruning is reading fewer folders. A filter on event_date read 1 of 21 folders; a filter on host had to read all 21. Partition on what you filter by.
    4. 
          
  4. Read the plan, do not assume. EXPLAIN EXTENDED lists the exact folders a query will read. One path means pruning worked.
    5. 
          
  5. Column formats pay off twice. Parquet was about a third of the JSON size, and summing one column was about twice as fast, with the same answer. With Snappy compression it would be smaller still.
    6. 
          
  6. Bucketing has two uses. Sampling by host, and joins between tables bucketed the same way. Otherwise it is extra complexity.
    7. 
          
  7. Window functions build baselines. Comparing each host with its own history finds "unusual for this host", which is what behavioural detection needs. On random test data there may be nothing unusual to find, and that is a correct answer.
    8. 
          
  8. One catalogue, many engines. Spark SQL read the same tables through the same metastore without redefining anything.
